# Архитектура проекта Taskbox-api 

**Taskbox-api** — это REST API сервис для управления списком задач (To-Do), построенный на фреймворке **FastAPI** с использованием легкой реляционной базы данных **SQLite3**.

## 1. Технологический стек
* **Язык:** Python 3.10+
* **Веб-фреймворк:** FastAPI
* **База данных:** SQLite3 (хранится локально в одном файле `taskbox.db`)
* **ORM (работа с БД):** SQLAlchemy (позволяет работать с таблицами БД как с обычными классами Python)
* **Валидация данных:** Pydantic (встроен в FastAPI, проверяет входящие и исходящие JSON-данные)
* **ASGI-сервер:** Uvicorn (для запуска приложения)

---

## 2. Структура папок и файлов

Проект организован по модульному принципу: каждый файл отвечает за свою конкретную задачу.

```text
taskbox-api/
├── app/
│   ├── __init__.py          # Делает папку app Python-пакетом
│   ├── main.py              # Точка входа: создание FastAPI приложения и подключение роутов
│   ├── database.py          # Настройка подключения к SQLite3 и создание сессий БД
│   ├── models.py            # SQLAlchemy модели (описание таблиц в базе данных)
│   ├── schemas.py           # Pydantic схемы (валидация запросов и ответов API)
│   ├── crud.py              # Логика работы с БД (Create, Read, Update, Delete)
│   └── routers/
│       ├── __init__.py
│       └── tasks.py         # Эндпоинты (URL-адреса) для управления задачами
├── taskbox.db               # Файл базы данных SQLite (создастся автоматически при запуске)
├── requirements.txt         # Список зависимостей проекта
└── README.md                # Инструкция по запуску и описание проекта
```

## 3. Описание компонентов

### `app/database.py` — Слой базы данных
Отвечает за соединение с файлом `taskbox.db`. Здесь создается `engine` (движок SQLAlchemy) и генератор сессий `get_db()`, который безопасно открывает соединение с БД на время одного HTTP-запроса и закрывает его после.

### `app/models.py` — Модели данных (БД)
Описывает, как данные хранятся в SQLite. Для базовой версии достаточно одной таблицы `tasks`:
* `id`: Integer (Primary Key, автоинкремент) — уникальный номер задачи.
* `title`: String — название задачи (обязательное поле).
* `description`: String — подробное описание (опционально).
* `is_completed`: Boolean — статус выполнения (по умолчанию `False`).
* `created_at`: DateTime — дата и время создания задачи.

### `app/schemas.py` — Схемы валидации (API)
Определяет, какие данные API принимает от пользователя и какие возвращает обратно:
* `TaskCreate`: поля, нужные для создания задачи (`title`, `description`).
* `TaskUpdate`: поля, которые можно изменить (все поля опциональны: `title`, `description`, `is_completed`).
* `TaskResponse`: полная модель задачи для ответа клиенту (включает `id` и `created_at`).

### `app/crud.py` — Бизнес-логика (CRUD)
Содержит функции для прямого взаимодействия с базой данных:
* `get_tasks()` — получить список всех задач.
* `get_task(task_id)` — найти одну задачу по ID.
* `create_task(task)` — записать новую задачу в БД.
* `update_task(task_id, task_data)` — обновить данные существующей задачи.
* `delete_task(task_id)` — удалить задачу из БД.

### `app/routers/tasks.py` — Маршрутизация (Эндпоинты)
Принимает HTTP-запросы от клиента, вызывает нужные функции из `crud.py` и возвращает результат или HTTP-ошибку (например, `404 Not Found`, если задача не найдена).

### `app/main.py` — Точка входа
Инициализирует экземпляр `FastAPI()`, создает таблицы в базе данных при старте (если их еще нет) и подключает роутер из `tasks.py`.

## 4. Спецификация API (Эндпоинты)

Базовый префикс для всех запросов: `/tasks`

| Метод | URL | Описание | Тело запроса (JSON) | Код ответа |
| :--- | :--- | :--- | :--- | :--- |
| **POST** | `/tasks/` | Создать новую задачу | `{"title": "Купить молоко", "description": "2.5%"}` | `201 Created` |
| **GET** | `/tasks/` | Получить список всех задач | — | `200 OK` |
| **GET** | `/tasks/{task_id}` | Получить задачу по её ID | — | `200 OK` / `404` |
| **PATCH** | `/tasks/{task_id}` | Частично обновить задачу (напр. отметить выполненной) | `{"is_completed": true}` | `200 OK` / `404` |
| **DELETE** | `/tasks/{task_id}` | Удалить задачу | — | `204 No Content` |

---

## 5. Поток обработки запроса (Жизненный цикл)

1. **Клиент** отправляет `POST`-запрос на `/tasks/` с JSON-данными.
2. **FastAPI** проверяет входящий JSON через схему `TaskCreate` (`schemas.py`). Если данные неверны, сразу возвращает ошибку `422 Unprocessable Entity`.
3. **Роутер** (`tasks.py`) передает проверенные данные в функцию `create_task()` из `crud.py`.
4. **CRUD-функция** создает объект модели `Task` (`models.py`) и сохраняет его в `taskbox.db` через сессию из `database.py`.
5. **FastAPI** преобразует сохраненный объект БД в JSON с помощью схемы `TaskResponse` и отправляет клиенту.

## 6. План развития (на будущее)
Когда базовая версия будет готова, архитектуру можно легко расширить:
1. Добавить таблицу `users` и авторизацию по JWT-токенам (чтобы у каждого пользователя были свои задачи).
2. Добавить фильтрацию в `GET /tasks/` (например, `?completed=true`).
3. Подключить Alembic для управления миграциями базы данных.
